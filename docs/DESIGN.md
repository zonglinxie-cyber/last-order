验收证据在 `audit/experience-v2/验收记录.md`（按轮次，附截图名与探针输出）；本文只留结论和推导。

## 全局语法：一句话一个槽

美妆柜台的这门生意里，导购说的每一句话都是**当场、对人、说一遍**的。玩家读界面用的是同一套习惯：一句话在两处出现，就会被读成"两件事"，或者怀疑自己漏了什么。所以本项目把"**这一屏这一句只有一个地方在念**"当成硬约束，而不是排版洁癖。

由此推出三条可判定的规则（每条都有 e2e 或规则测试钉住，不靠人眼复查）：

1. **一句话一个槽**：同一屏里，一条信息只由一个 DOM 槽念出。要挪位置可以，要在同一屏出现两遍不行。
2. **措辞只写一份**：文案由 `dynamic-counter-prototype/src/campaign.ts` 一处导出，两个 UI 各自 import 去读。禁手写副本 —— 一旦有副本，改数字那一轮就会漏改，P17 的「预算 ¥3,200 · 上限 3 件」正是这么分裂的（见下）。
3. **禁解说层**：不加面板、仪表、徽章、"提示框"。规则要玩家自己撞见，撞见后由现场里已经存在的那一格（她的诉求、柜上的报价、栏位里的体力）说出来。

**判定"重复"必须测可见性，不能只看文本。** 两条实测教训：

- `getBoundingClientRect()` 对 `display:none` 的子节点返回 0×0，但对**被折叠的 `<details>` 内部**返回的是正常尺寸 —— 探针因此报了两个"重复"（「妆面基本完整…」「近看有粉感…」），实际 `details.open === false` 且 `checkVisibility({ contentVisibilityAuto: true }) === false`。**已撤回，没去"修"。** 现在的数法：文本相等 + `width >= 2` + `checkVisibility({ contentVisibilityAuto: true })`。
- 反之，两个槽都在屏上、只是离得远（1280×720 上顶边 343 和 518、都没被裁）， containment 扫不出来 —— 那一条是**专门量矩形**才抓到的。所以"有没有重复"要两遍扫：一遍全文本计数，一遍对嫌疑槽量矩形。

## P16：连带那一排摆到同一屏里

**问题**：沙盘四格按内容宽度排（实测旧布局 `134×53 / 146×53 / 148×53 / 197×53`），前三格 428px 放得下 522 的左列，最贵的「批量追加」197px 放不下 → 整排折两行，第四格掉到可见带以下 95~120px。玩家要自己滚才看得全一个四选一。

**改法与取舍**：

- `flex:1 1 0; min-width:0`（等宽）而不是 `flex-wrap` 或缩字号。理由：档位是**横向比**的四个选项，竖着堆就变成四块独立信息，读不出"按一档往上加"的梯度；`flex-basis:0` 同时消掉了"按内容宽度决定折行"这条隐式依赖。
- 挂载那一次程序自己 `scrollIntoView({block:"nearest"})`，声明在原来的 `scrollTo({top:0})` **之后**，所以是它说了算；只滚挂载那一次，之后玩家自己滚的位置不再被覆盖 —— 每次渲染都滚会把玩家的阅读位置抢走。
- 滚过去会切掉右列报价单的头一行（1024×700 上滚过 96px，报价单从内容第 45px 起，头一行「云纱柔焦粉底 × 1」被切约 51px），所以 `.close-review > .order-quote { position:sticky; top:0; align-self:start }`。
  **这是全项目唯一允许的一处 sticky**，要记住它和 P13 撤回过的那条不是一回事：那条是 `sticky; bottom:0`，一条带横切在连带按钮中间；这条住在自己的那一列里，盖不到任何东西。`align-self:start` 是必须的 —— 不 start 它就涨满格子，没有可滑余量，sticky 等于没有。
- 手机版没有折行问题（42% 抽屉下 `scrollHeight 356 = clientHeight 356`，四格底边离抽屉底还有 55 屏幕像素）。它坏的是**字号**：`.bundle-row` 的 `span/small/em` 是 8px/7px/7px，而 `prototype.css` 那一遍 12px 下限漏了这一排，P15 新写的那句规则说明正好落在 7px 那一格。8/7/7px 相对正文 12px 是"小一半"，等于没解释。
- 补到 12px 的连带代价，量出来才敢动：格子设计像素 44→78、那一排在 390×667 上 37→64 屏幕像素，42% 的抽屉放不下，`提出成交` 底边超出抽屉 11 屏幕像素（≈17 设计像素）→ 成交那一档的抽屉 42%→48%。
  **这里如实记下**：42% 是 positive 独有的，比其它阶段的 46% 还矮，而它那一档正文最长 —— 这个不一致本轮没解释成因，只是被测量逼着抬平了。

**矮屏不改成删文案**。844×390 那一档可见带只有 161px，装不下 214px 的一排，所以那条用例只断"这一排的开头（eyebrow + 第一格）在视野里 + 抽屉是程序滚过来的（`scrollTop > 0`）+ 报价单没被切"，剩下按"矮屏靠滚动消化"。这不是让步，是这一档唯一不撒谎的断言。

## P17：同一屏念了两遍的三句

**先量，再改。** 三个来源各自独立：

| # | 重复 | 两个槽 | 根因 |
| --- | --- | --- | --- |
| 1 | 她的说法（descriptor） | 右上阅读面板 `.customer-reading > .eyebrow` vs dock 身份格 `.dock-person small` | dock 那一格是**选人时**的身份说明，接待时没换内容就继续挂着 |
| 2 | 体力那句（`energyWord`） | 栏位 `.rail-energy` vs dock `.dock-person p` vs 成交卡 | 三个地方都想要它，没人是"正主" |
| 3 | 她的预算与上限 | 沙盘：诉求板 `.demand-budget`（手写副本）vs 连带行 `bundleHint`；手机版：晨会简报 `story.threat` 与下面一条「罗曼 · 08:52」转发卡 | 3a 是措辞副本导致的；3b 是把规则提示安到别人头上 |

**哪个槽留下**：

- 她的说法 → **右上阅读面板**。接待时那里才是"正在看她"的那一格；dock 那一格只保留名字。
- 体力 → **栏位 `.rail-energy`（≥1101px 的正主）**。dock 那一格和成交卡上的副本降级为 `.rail-fallback`，只在栏位整块收起时（`@media (min-width:1101px){.rail-fallback{display:none}}`）接手念。这不是"两边都留一份保险"，是把"谁在这档说话"写成一条 CSS 事实，e2e 在 1280×720 和 1024×700 各测一次计数 `=== 1`。
- 预算与上限 → **沙盘拆成两个槽各一句**：诉求板念 `demandBudgetWord(customer)`（她自己的两条事实），连带行念 `BUNDLE_MINUTE_HINT`（多出来那一分钟买的是什么）。原来的 `bundleHint` 把两句焊在一起，于是诉求板念一遍、连带行又念一遍。
- **手机版不拆**，`.bundle-row > em` 仍是一整句 `{demandBudgetWord} · {BUNDLE_MINUTE_HINT}`。

  数值推导（探针 `scrollHeight - clientHeight`，设计像素，390×667 与 320×568 数字一致）：**现状就没有富余** —— 观察阶段 4、询问/提问/选定 0、成交阶段 1，而 P16 的契约是 `overflow ≤ 1`。成交那一档已经贴着上限（那一屏正文最长 + 四格 + 两个关单按钮），再往 `.bundle-row` 里加一行 `<p className="demand-budget">` 实测把成交顶到 **24**、观察顶到 27，P16 两条用例同时红。中途试过第三条路：把她的预算塞进上面已有的剥离行，量完还是溢出，撤回。
  **所以两个 UI 在这里故意长得不一样**：沙盘两个槽各一句，手机版一个槽接回一行。玩家读到的句子一模一样，措辞仍只有一份。差异写进代码注释和这条记录，不假装统一。

- 手机版晨会简报：删掉那条「罗曼 · 08:52」转发卡。它把当天风险原话重念一遍，还假造了一个发言人。

**规则一个字没动**：`campaign.ts` 里只替换了导出文案（`bundleHint` → `demandBudgetWord` + `BUNDLE_MINUTE_HINT`），`BUNDLES`、`unitsWanted`、`orderQuote`、五日目标 ¥21,000、清洁基准都没碰。规则测试 61 → 62（新增的是"两句不互相重复"的措辞契约，不是数值）。

## P18：动作行做成抽屉的脚（顺手拆掉一条从没生效的"48%"）

**要解的那一屏**：手机版断货/调货那一档，正文 516 设计像素压进 390 的可见带，`提出成交` 落在折线以下 70 屏幕像素（≈108 设计像素）。修法方向早记下了：像沙盘那样把动作行钉在抽屉脚上。这本来就是运行时契约里那条"app-owned fixed chrome 留在 `MobileScroll` 外面"，不是新发明。

**改的东西**：`.consultation-foot` 成为 `.consultation-dock` 的第二个 flex 子元素（`.consultation-controls` 之外），`flex:1 1 auto; min-height:0` 给滚动区，脚 `flex:0 0 auto`。不给脚写魔法高度：脚多高，滚动区就少多少。

### 量出来的三件事

1. **`max-height:46%` 一直夹着内联的 `height:48%`**（两者都是百分比时 max-height 赢）。P16 记的"成交那一档抬到 48%、42% 会把提出成交顶到抽屉外"**从没渲染过**：实测抽屉高 45.8%，而且 48% 那一档三枚面部线索离抽屉顶的屏幕像素 `(42,-2,4)` 与 46% 各档**一模一样**。这条现在以 CSS 为准：删掉 `max-height`，抽屉高度只由 `Prototype.tsx` 那一串阶段说一处。
2. **脚是要还高度的**：单行 59 设计像素（1px 分隔线 + 6 + 44 + 8），拒绝那一档两行 102。成交那一档把动作行搬出去，正文 516 → 464、可见带 390 → 328；净结果是**四格下沿离脚 4 设计像素**（不滚就在），而 `提出成交` 从"折线以下 108 设计像素"变成"永远在带内"。断货那一档的四格仍要滚一下 —— 这一条如实钉进测试（`scrolls > 0`），不假装解决了。
3. **矮的那一档最先被脚吃掉**：观察档 17% 时，她念第一条线索那句话被压在脚下 10 / 8 屏幕像素（390×667 / 320×568）。抬到 **20%** 后余量 7 设计像素。中途试过 19%，实测只剩 1 像素贴线 —— 自由输入那一档她的句子可能更长，所以不留 1 像素。46% 那一档**不再抬**：48% 会把脸颊、鼻翼两枚线索盖进抽屉里（-13 / -7 屏幕像素），脸才是主玩面；两枚线索在 46% 已经各自盖住 2 / 1 像素，这是既有代价，不是本轮新增。

### A/B（同一支探针，390×667，数字是"这一行离折线多少"，正数=要滚）

| 档位 | 修前（动作行在滚动区里） | 修后（脚 59） |
| --- | --- | --- |
| 进店 17/20% | 无 溢出 4 | 无 溢出 0 |
| 观察 1 条 | `primary-action` +4（按钮自己看不全） | 她的话 +10 屏幕像素（17% 那一档）→ 抬到 20% 后 -7 设计像素 |
| 提问 / 选定 | 无 | 无 |
| 成交（顺畅） | 四格 -42、`close-actions` -10，溢出 1 | 四格 -4，溢出 8（多出来的是脚下呼吸位） |
| 断货报价 | 四格 +38、**`close-actions` +70** | 报价与第一行调货在带内，四格 +76（滚一下全出来） |
| 反应不对 | 报价 +7（两行动作在正文里） | 报价 +5（脚 102，滚 15 像素消化） |

### 契约怎么改

- `bundle-ask.spec.ts`：`overflow ≤ 1` 这个替身不再成立（它现在把脚下的呼吸位也算进去），改成按几何量 —— **四格下沿 ≤ 脚的上沿**、脚在 `.consultation-controls` 之外、脚整块在抽屉带内（`.consultation-dock` 是 `overflow:hidden`，掉出去不是"要滚"而是直接被裁）。字号 12px 下限与"预算那句只念一遍"原样保留。
- `consultation-layout.spec.ts`：`接受拒绝` 的界从"滚动区下沿"改成"抽屉下沿"，并补一条"滚动区这一档确实还要滚"，否则下面那句"拖一下会滚"是空断言。
- 新增 `closing-foot.spec.ts`（两档视口 × 两条）：脚不跟着滚、`scrollTop === 0` 时报价单 + 第一行调货 + 脚下每颗按钮都在带内、脚下按钮 ≥44px、滚到底四格全出来；以及观察档她那句话不被脚盖住。
- **反证跑过**：把脚搬回 `MobileScroll` 里 → 6 红，消息是"动作行又住回滚动区里了 / 又搬回滚动区里了"；只把观察档高度改回 17% → 2 红，"她刚说的那句话有 10（8）屏幕像素落在脚下"。
- 这里也撤回一个以前的验收口径：`stock-transfer.spec.ts` 里那句 `提出成交` 点击是绿的，**从来不是"看得见"的证据** —— Playwright 会自己滚。这一轮的断言全部按 rect 量，不靠点击通过。

**规则与经济一个字没动**：`campaign.ts` 无改动，62 条规则测试不变。截图 `p18-baseline-*.png` 是修前那一屏，`p18-transfer-foot-*.png` 是修后。

## P19：账本要能对回来 —— 钱写在动它的那一行上

**要解的那件事**：结局那一屏左边是大数字（¥22,930），右边是五日因果账本。玩家顺着账本往回加，加不出那个数 —— 有些钱动了累计，账上只留下一句不带数额的话。这不是算错钱，是**看得见的原因对不上看得见的结果**，而柜台这份工作的全部说服力就在"能对回来"。

### 先分清两个"差"（我第一轮把它们混过一次）

| 口径 | 清洁路线 | 私域路线 | 含义 |
| --- | --- | --- | --- |
| `sales` − Σ 账本上带 ¥ 的行 | 1,680 | 8,960 | 玩家**看得见**对不上的那部分，本轮解的就是这个 |
| `sales` − Σ `orders.amount` | 980 | 8,260 | 数据结构口径：不进收银小票的钱（私域补单、私下转单、闭店调整、退单冲回） |

第二个差**不是缺陷**：私域复购和唐可转的单本来就不该有收银小票。本轮只解第一个。

11 条路线全部量过（探针 `/tmp/p19-before-after2.ts`，旧模块从 `git show HEAD:` 取到 `/tmp/p19-before/`，同一个审计器喂两边）：非私域的 8 条路线修前一律差 **1,680**，`roster` 差 **8,960**，`roster+face` 与 `face+pull+transfer` 差 **7,000**；修后 11 条**全部差 0**。

修前"动了钱却没写数额"的行，逐条数出来只有这些（`/tmp/p19-which5.ts`）：

- 每一条路线：**赵青加你微信，下了一单修护** +¥1,680（第 5 天晨会私下成交，不进小票）；
- 私域路线再多 6 条：**沈薇 / 小雨 / 周姐 / 段小姐 各 ¥980、赵女士 / 安姐 各 ¥1,680** 的微信补单，合计 ¥7,280。

**两条自我更正，如实记着**：① 本轮开工时的口径是"差 ¥980"，那是上表第二行（数据结构）的数，玩家可见的差其实是 1,680；② 我第一版审计器只认 `· ¥` 这种写法，而旧代码的闭店调整写的是 `：−¥490`，于是把两条**本来就带着数额**的行误报成"本轮补上的"。改成认两种写法之后，闭店调整那两条从清单里掉了出去 —— 它们这轮只换了分隔符。

### 改的东西

- `campaign.ts` 导出 `receiptLine(text, amount)`：把 ` · ¥1,680` / ` · −¥490` 拼在句子末尾，**由规则在动 `sales` 的那一处调用**，不在 UI 里另算。挂上的地方：`resolveSale` 小票、`settleDayEvent` 闭店调整、`applyPayback` 退货冲回、`applySampleReturn` 小样回单、`applyMemberRepeat` 微信补单、`applyDawn`（唐可转单 / 赵青下单 / 赵女士退单）、`applyFinale` 批量单暂扣。
- **负数写"实际掉下来多少"**：`sales` 有 `Math.max(0, …)` 兜底，所以行内记 `-Math.min(charged, s.sales)`。大数字只掉了 300，行上就写 −300，不写应收 1,680 —— 否则账本又会比大数字多算一笔。
- 小票那一行写**真入账的数**（跟陆遥拼单就是半份），整单在报价单和拼单那行各自念过一次，够了。
- `landedToday` 从整句相等改成"这句话开头"（`text === entry.text || entry.text.startsWith(text + " · ")`）：账本行末尾挂了钱之后，晨会"兑现的那一句"不能再靠字符串全等来认。
- 根沙盘**删掉第二份钱**：结局屏原先在因果账本之外另排一叠 `.order-line` 小票，同一单在那儿是净额 ¥490、在因果行是整单 ¥980 —— 同一屏两个数，正是 P17 那一类。删掉那一叠和它的 CSS 规则，钱只由因果行念。
- `SPLIT_WORD`（"与陆遥各半"）从 `campaign.ts` 导出，沙盘那半句不再手写副本。

**为什么不加 `money[]` 字段**：那是最直觉的做法，但会逼 `SAVE_VERSION` 6→7，正在第五天中途的玩家存档会被丢掉；而数额本来就能从"动钱的那一处"就地写出。挂在规则里还顺带堵死了漂移 —— 以后谁加一条动 `sales` 的逻辑，`ledgerSum` 那条规则测试立刻红，不需要他记得去改 UI。

### 契约与验证

- 规则层新增 1 条（62 → **63**）：`ledgerSum(s) === s.sales` 跑 9 条路线；再加"每一行带 ¥ 的行都必须是真的钱"的反向检查、私域路线的构成（17 条 ¥ 行 = 8 张小票 + 6 条微信补单 + 赵青 + 2 条闭店调整），以及拼单那一行必须写净额（`沈薇带走 2 件柔焦（与陆遥各半） · ¥980`）。
- 玩家侧审计器 `tests/ledger-yuan.ts`：从**渲染出来的 DOM** 里把 ¥ 加起来，不看规则内部。三处独立断言同一个数 —— 根沙盘 e2e `22,930`（替掉原先数 `.order-line` 个数的 9）、手机版 e2e `22,930`、以及零成交那一周 `0`（什么都没卖就不该有一行钱）。
- **反证跑过**：删掉赵青那一行的 `¥` → 规则测试与手机版 e2e 同时红，报的都是 `actual 21250 / expected 22930`，差额正好等于上表那一格 1,680。

## P20：开店前那一遍效期自查 —— 把条例里那条义务变成一分钟的选择

**要解的那件事**：前面几轮的内容深度都挂在"卖"上（配货、断货、连带、私域）。但柜台上真有一件事每天都做、游戏里完全没有：**货的效期**。这一轮把它做成晨会前的一步取舍，而不是又一条判词。

### 依据与一条否证

《化妆品监督管理条例》第三十九条要经营者**定期检查并及时处理**变质或超过使用期限的化妆品 —— 这是这一步的落脚点：查是义务，不查不是"另一种玩法"，是台账上少一条处理记录。

同时量到一条**否证**：翻了条文和配套规范，**没有任何一条要求"一客一换粉扑 / 一次性涂抹棒"**。美妆内容深度很容易顺手拿卫生当依据（上一轮我差点这么写），但那条在本项目的依据链上站不住，所以这一机制**不建立在卫生上**，只建立在效期与处理记录上。

### 做成什么样

- **整周只查一次，只在下第 3 天早上出现**：`EXPIRED_SAMPLING = { fromDay: 3, units: 2, minutes: 1, compliance: 6, standing: 3, penalty: 4 }`。为什么是第 3 天：抽屉最下面那排去年批号要被人想起来，得先有"巡店要翻处理记录"这句话 —— 那句写在第 3 天晨会，整周只念一次。为什么只有 2 支：一周 8 支小样，一次翻出 2 支是"顺手能翻到"的量，翻出 5 支就成了数值惩罚。
- **价写在按钮上**：`开店前查一遍批号 · 下 2 支 · 晚开门 1 分钟`，下面那行只说买到什么（`当场下架，台账上留下一条处理记录`）。查这一遍走 `spendAttention(..., 1)`，而开门前那 1 分钟确实会磨队列耐心（`startNextDay` 已经播好 `waitMeters`），所以"晚开门"不是装饰文字。
- **不查的代价跨日才来**：到期那支派给谁，第二天晨会那个人问回来一句（`赵女士 · 微信`：批号是去年的），扣 4 分信任 + 4 分合规，**钱一分不动**。
- **上限就是 2 支**：`expiredSamplesGiven` 数 `sample-expired:*` 旗子，派满两支就到头 —— 不查不会滚成整周灾难。
- **客诉那行不带 ¥**：它不动 `sales`，所以按 P19 的契约它**不该**有数额。（本轮开工时我自己写的任务记录要求"客诉冲回那行必须带 ¥"，那条前提是错的，量完改掉了：给不动钱的行挂 ¥，账本立刻对不回来。）

## P21：现场那一屏不再把同一个人念两遍

**要解的那件事**：审计说手机版"现场"那一屏把同一个人念了两遍。先核，核完确认有，而且比报上来的多——两个入口各一处，手机版还多一处。

### 量到的三处（改之前）

| 屏 | 两个槽 | 量到 |
| --- | --- | --- |
| 手机版现场 | 墙上气泡 `.actor-bubble.stage-bubble` vs 面板引号 `.inspect-quote` | 同一个人的同一句原话 |

| 沙盘现场 | `.floor-voice` vs `.floor-inspect`（"她正在说"） | 空地那句和抽屉里是同一句 |

### 一条规则，不是四处补丁

**稳定槽念你点中的人，会动的槽只念你没点中的人。** 面板/抽屉是稳定槽（读整句的地方），墙上气泡、页顶那行、名单是会动的槽。现场只剩她一个时，页顶那行才回到她身上（`ambient.find(notFocused) ?? ambient[0]`）——不能因为去重就把"还有谁在等"这件事念空。

沙盘那格顺带买到一个好处：空地那句现在报的是**你没选中的那一位**，正好是第 1 天副标题写的那句"两个顾客，只能先抓住一个"。原来它跟着选中的人念，等于把已经在看的那句话再念一次。

`firstClause()`（取到第一个句号）只用在沙盘空地那一格：`.rescue-scene.tight-plates .floor-voice` 是 `max-width:258px` + `white-space:nowrap` + 12px 字号，整句会被省略号截掉；整句在抽屉里念。原来手写的 `id === "shen" ? "先说好，我不缺粉底。"` 特例删掉了——`firstClause` 算出来的就是同一串字。

### 撞出来的两个几何洞（本轮真正花时间的地方）

**① 进场那一帧，墙上的话和点亮的名牌对不上（实测差 128px，契约是 <44px）。** 根因不在文案槽位，在落位：`poses` 还是空的，`poseOf` 用"家里"那一格兜底；紧接着落位效果把人放到门口，于是 `transition:left .38s linear` 让**名牌滑过整块沙盘**（56%→12%＝172px），而气泡没有 transition，一步就落到门口。HEAD 上同样存在，只是那时 `floorBeat % 4` 点中的是 index 0，差 43px、勉强过；P21 换了"不念点中那个人"的相位，就把这条露出来。修法：兜底改成人**已经在门口、正往自己那一格走**（带 `destLeft/destTop`，所以算"走动中"，两位一起进场也不会把名牌叠在同一格）。

**② 走得久了，名牌会滑进控制台面板里。** 探针 `/tmp/p21-clr.log`（320×568，逐 320ms 取样）：余量 1.7 → 7.4 → … → **−0.1px**，掉下去那几步是罗曼从收银位（61%）走到旁边那一格（63%）；390×667 同一趟最低 3.6px，也低于契约的 4px。旧断言量不到，是因为它一进场就按「停」——它注释里记的 844→21.2 / 667→12.3 / 568→7.4 正是"那一刻恰好站着的那一位"。修法：把最矮那一排整个抬进安全带（`entrance` 12/62→16/58、`openLow` 61→58、`checkout` 61→57、罗曼那一格从散在代码里的字面量提出来成 `WAYPOINTS.romanSide` 66/59、`rivalHold` 58→54 以保住门口与游荡位原来那 4% 的纵向差）。抬完按 26 次取样 ×2 天 ×3 档复量：844 最低 24.4、667 最低 14.9、568 最低 9.5；按下暂停那一刻的余量变成 58.5 / 32.3 / 24.4。

## P22：现场那句停得住（台词对一个状态，不再对一拍）

**要解的那件事**：P21 记下的第一条待办。墙上气泡和面板引号都按 `floorBeat` 取模换句，而 `floorBeat` 每 380 毫秒进一格（`Prototype.tsx` 的 `setInterval(.38 * floorSpeed)`）——一句话只停 380 毫秒。量了台词本身：`opening`/`need` 共 20 条，中位 **24 字**、最长 **38 字**；`opening` 的第一句最长 **18 字**、中位 **12 字**。按 5 字/秒（保守的中文默读速率）算，原来那句 38 字的要 7.6 秒才念得完，屏上只给了 0.38 秒。

### 改法：一句话对一个状态

`customerBubble(customer, meter, beat, resumed)` / `staffBubble(id, contested, beat)` 换成 `customerSpeech(customer, meter, resumed, rivalNear, whole?)` / `staffSpeech(id, contested)`：**没有拍子参数**，同样的状态永远同一句，话变了是因为现场真的变了。

| 状态（从上往下第一个命中） | 那句 |
| --- | --- |
| 接待还没结束 | 我还在这儿。 |
| 耐心 ≤ 1 | 你们还接不接？ |
| 耐心 ≤ 2 | 我真的要走了。 |
| 陆遥靠过来（`rivalApproach > .4`） | 对面也在看我。 |
| 耐心过半 | 我时间不多。 |
| 其余 | 墙上＝`firstClause(opening)`，面板＝整句 `opening` |

原来那串轮播里剩下三条（"这单我也可以做。""她之前用过我们家持妆。""你们今天排面一般。""今日排名已更新。""客单，别只顾着聊天。"）没有对应状态，删掉；其中陆遥那句持妆在 `RIVAL_INTERRUPTIONS.shen.quote` 里本来就有整句，抢单事件里会说，不算丢内容。`customer.need`（中位长句）从现场撤掉：**她的核心诉求不该在开口之前白给**，那是提问环节要换出来的东西。

### 说话的人也跟着现场，不按拍轮

`voiceTarget(candidates, meters, closeness)`（`floorLife.ts`）：没被点中的在场人里，陆遥靠过来先听她（截胡预警），否则听**耐心最少**的那位客人，没客人了才轮到同事。原来手机版是 `onFloor[floorBeat % n]`（纯轮转），根沙盘是 `available.find(id => id !== focus)`（先来的那位）。这一格从此回答的是当天副标题问的"只能先抓住一个"，而不是"第几拍了"。

沙盘的「她正在说」也一并改成 `customerLine(id, true)`：原来写死 `selectedCustomer.opening`，她已经看到表（`.dock-person p` 写着「开始看表」）面板还像她刚开口。现在面板与墙上同一条规则，只是面板给整句。顺带把"点中陆遥时空地还报陆遥"那一格堵住（`focus !== "luyao"`）。

### 契约

- 新增 `tests/floor-speech.spec.ts`（手机版 6 条，纯函数、不开浏览器）：每位客人×每档状态的墙上那句 **≤18 字**；状态→句子的映射与优先级（要走优先于"对面在看"）；面板那句不短于墙上；`voiceTarget` 三点（按耐心、陆遥靠过来、只剩同事）与空返回。**注**：这份只能挂在 Playwright 上——`node --experimental-strip-types` 要求相对导入带 `.ts` 后缀，而 `tsconfig` 的 `moduleResolution: Bundler` 又禁止带（TS5097）。试过给 `floorLife.ts` 的导入加后缀，`tsc` 立刻红，已撤回。

## P24：一支小样的三条去处摆到同一屏可比（留小样那句"买到什么"）

**要解的那件事**：P23 记的第一条待办。留小样那一颗原来只写 `留小样 · 8`（代价），而它和"迎上去"花的是**同一件资源**（整周 8 支，P12/P14）、买到的是**完全不同时间尺度的东西**：一支当场把人请回来，一支要等当晚跟一句、她那一单没成、再排到她的回柜那天。这两条线在界面上从来没并排过，玩家只能把第二颗当成第一颗的弱版。

### 先看规则到底给了什么（文案不许超过规则）

| 这一支花在哪 | 规则实际做的 | 界面上那句只写 |
| --- | --- | --- |
| 迎上去（中庭） | `samples −1`；她耐心回满；离柜 2 分钟从另一头扣；**不打** `sample:` 旗 | `换她重新站回柜台前 · 这一支不回柜`（P23） |
| 留在柜台 | `leaveSample`（`campaign.ts:1171`）：`samples −1`、`trust +4`、打 `sample:<id>`。钱由 `applySampleReturn`（`:609`）兑，要**四件事同时成立**：到了她那一天（`SAMPLE_RETURNS` 的 `fromDay`）、当晚跟过一句（`touched:`）、她那一单没成（`served:x:refused` 或 `lost:x`）、这一支还没结算过 → `+¥620`、`+5 信任` | `她这一单没成才回得来 · 当晚还得跟一句` |
| 谁都没给（加微信按不动那一格） | `canAddMember` 要 `sample:<id>` 或当天接完这一单 | `先留一支小样，或接完这一单` |

那句里**故意没有 ¥620、也没有第几天**：这两个数是规则里的常量（`SAMPLE_RETURN_SALE`、`fromDay`），写进按钮就是替她保证"她一定会回来"，而规则给的条件恰恰是"回不来就不入账"。留小样买的是**等**，不是现在 —— 上一轮（P14）把到货排成日期之后，"等"才第一次成为游戏里的一个真选项，这一句是让它在按钮上可见。

### 一个谓词，三个入口共用

`canLeaveSample`（`campaign.ts:1119`）和 `LEAVE_SAMPLE_RETURN`（`:1115`）一起导出。沙盘现场那颗（`src/CounterGame.tsx:384`）、接待抽屉脚上那颗（`:420`）、手机版同一颗（`Prototype.tsx:426`）都用**同一个谓词**做 `disabled`、用**同一个常量**做那句。闸门写在按钮上、理由写在别处，两边就会各自漂移：界面亮着、按下去一个数都不变。

`campaign-rules.test.ts:152` 把这条契约钉成"**按得动就等于收得下**"：对抽屉空的 / 已经给过一支 / 还能给三档各 `assert.equal(canLeaveSample(s, id), leaveSample(s, id) !== s)`（规则里"什么都不做"的那些状态，按钮必须同样按不动）。同一节再钉回柜要三件事同时成立：她当场买过 ⇒ 不再回柜一次；没排到她那天 ⇒ 问也问不回来；齐了 ⇒ 正好 `SAMPLE_RETURN_SALE`。最后钉那句本身：`assert.doesNotMatch(LEAVE_SAMPLE_RETURN, /[¥0-9第]/)`。

### 版式：整行的注，贵的不是它那 16px，是它把后面的按钮各顶下去一行

第一版把三句都做成 `.floor-actions > p`（`flex-basis:100%` 的整行），390×844 当场散掉：**四颗按钮被拉成四行**，内容 311px 压进 169px 的可见带。机制是 `flex-wrap` 行里一个 `flex-basis:100%` 的项会独占整行并让后面的项换行 —— 所以**一句注的代价约等于一整行按钮高（≈52px），不是它自己那 27px**。

改法是让每一格自己带自己的注：`.floor-action { display:grid; gap:3px }`（按钮在上、注在下），注不再是 `.floor-actions` 的直接子项，行只由按钮自己排。窄屏那一档给 `.floor-action` `flex:1 1 0`、按钮 `white-space:normal`（≤650 那条 `> button` 的 `nowrap` 因此从 `.floor-actions button` 收成 `.floor-actions > button`，否则格子内层那颗会横着撑破）。剩下两类整行注（"你还在接待 X"、"今天先到这里"）继续走 `.floor-actions > p`。

## P26：一周的账不只按总额结 —— 但"连带率"这一项不许做成记分牌

**要解的那件事**：从 P23 起就记在待办里的"品类结构考核（内容深度候选）"。这一轮先调研、先量，再决定落地成什么。

### 调研能引到的和引不到的

- 口径是清楚的：**连带率 UPT = 销售件数 ÷ 交易笔数**，且 **ATV = UPT × AUR**（TruRating）。这条恒等式就是"同一笔钱有三根杠杆"的数学形式，探针里八条路线逐条验过（`恒等式` 列全 true）。
- 数量级引不到：行业自媒体给过 1.2~2.0 / 2.0~3.5 / 3.5+ 三档（腾讯云开发者新闻），**那是自媒体分档，不是品牌公开考核表**；柜台级品类配比目标、派样→正装转化率、会员注册率基准都**没有可靠公开来源**。所以这一行不写"行业说 2.0 及格"那种话 —— 写了就是把我们查不到的数当成规则。
- 有依据的只有"方向"：非中性激励会让销售系统性把组合推歪（多任务委托代理文献）。这恰好是**不要计分**的理由，不是计分的理由。

### 口径：这一行为什么不带 ¥

`weekStructure` 只读 `s.orders` 与 `lost:` 旗，不新开存档字段。两个口径坑：

1. **`sales` 里有不写 orders 的钱**：唐可转单（`:712`）、小样回柜（`applySampleReturn` `:615`）、微信补单（`applyMemberRepeat` `:680`）。探针量到每条路线至少 ¥980 不在任何一张单上，私域那条 ¥8,260 —— 和 `campaign-rules.test.ts:289` 记的"17 行对得上"是同一件事。件数和金额放进同一句就是两种口径，所以那句**一个 ¥ 都不出现**（单测钉 `structureLine(state).includes("¥") === false`）。
2. **"这一周几位没等到"不能数 `s.lost`**：`startNextDay`（`:1267`）每天早上把它清空，它是"今天"的。数的是 `lost:` 旗（持久），而 `flag()`（`:454`）去重，所以量纲是"位"不是"人次"。

## P28：第 4 晚那一格「自己垫一支走单」—— 调研里最难看的一条，落成两数字一屏

**要解的那件事**：目标里"内容深度"这一项，前面几轮落的是**行业口径**（连带率、坪效、名单、效期）。这一轮落的是**行业里最不体面那一条**：`audit/research-2026-09/调研与改造方案.md` 第三节引虎嗅那句 —— "KPI 普遍完不成、大促才达标、**自掏腰包囤货**、完不成要交改进报告"。游戏此前只演了前半句（进度压力），后半句一个字没有：玩家落后时能做的只有"更会卖"，而真人在落后到补不回来那一晚，做的是**把自己的钱变成柜台的数字**。

### 这一格长什么样（两个数写在同一行）

```
自己垫一支走单
业绩 +¥980 · 你先掏 ¥686 · 台账上多一笔虚增
```

| 数 | 从哪来 | 去哪 |
| --- | --- | --- |
| ¥980 | `PRODUCTS.soft.price`（小票价） | 进 `sales` / `daySales`，一次；台账 `闭店调整 · 自己垫一支走单 · ¥980` 一行 |
| ¥686 | `ADVANCE_POCKET_RATE = 0.7`（内购 7 折）× 980 | **不进账本**，只发生在她自己的工资上 |
| −12 合规 / +6 唐可 | `ADVANCE_COMPLIANCE` / `ADVANCE_TANGKE` | 当晚的代价：账上多一笔对不上客人的钱，靠唐可替你张罗才开得出去 |

**为什么挑最便宜那支**：真被逼到这一步的人，先算的是"我掏多少"，不是"哪支好卖"。所以 `ADVANCE_PRODUCT = "soft"`，不是 1,680 的修护 —— 这一格不该是"收益最大"，该是"最不体面但当下最够"。
**为什么第 4 晚**：前三晚数字还来得及靠接待补，第四晚已经来不及了 —— 这正是它真实出现的时机，也是 `DAY_TARGETS` 里 4,400 那一档最疼的晚上。
**为什么价目写在按钮第二行**：P23/P24 立的语法（"买到什么"写在动作上）。只报 ¥980 的那一格会让人以为垫货不花钱，而那正是这条机制要被看懂的地方。

### 第 5 早按唐可出不出得掉分岔（`applyDawn`，认的是 `TANGKE_STOCK_GATE = 45`）

| 分支 | 旗 | 钱 | 别的 |
| --- | --- | --- | --- |

| 出不掉 | `advance-held` | **不冲回** —— 数字留在账上 | 合规 −6、柜位 −6，方敏要一份"这一支是谁买走的"说明 |

出不掉**故意**不退款：这格要留的那口不适就是"钱花出去了、数字是我的、客人名字写不出来"。行业那句的后半（交改进报告）落在这一支上。

## P34：柜台最容易越界的那一句 —— 只有普通备案的精华，嘴上承诺「用两周，斑就淡」

**要解的那件事**：目标里"内容深度"那一条，此前落地的三格全在**钱和货**上打转（连带 P16、垫货 P28、比价 P32）。真实柜台上最先出事的是**话**：一支只有普通备案的精华，BA 说一句"用两周斑就淡"就能多带走一支 —— 而这句话在游戏里根本没有入口，"越界"只剩"硬推"一种形态。P34 加的就是第二种：**同一排里多一颗按钮，当天多入账一支，代价分两次在后面收**。

### 这一格的三个"看不见陷阱"闸门（都是推导出来的，不是先写了再补测试）

`canClaim(s, id, product, bundle)`（`campaign.ts:286`）三个条件，少任何一个这一格就不出现：

1. **真能多带走一支**：`claimUnits(...) > forcedUnits(...)`。多不出支数还照收一次合规，那是"看不见的陷阱"—— 玩家按了一颗改变不了任何结果的按钮，只在台账上多一笔扣分。所以抽屉只剩一支（`repair:1`）、她是单件上限、或连带本来就要了两支，这三种情况下按钮不出现。
2. **不是最后一天**：`s.day < DAYS.length`。第 5 天按下去，那句承诺写着的两次代价（她查备案问回来、退货那天翻倍）**都落不了地** —— 那天没有"第二天早上"。这和断货那一屏删掉「等」是同一个判断（`restocks`）。
3. **回音只属于"当天之后"**：旗子写的是 `claim:<id>:<day>`，`applyDawn` 里 `if (next.day <= Number(day)) continue`（`campaign.ts:784`）。这道门是实测逼出来的：`openFloorState` **当天回到现场也会调 `applyDawn`**（`CounterGame.tsx:40,181`、`Prototype.tsx:170,354`），不带日次的话，成交后点一下「回到现场」就当下午被追问一次、信任提前扣掉。反证 B 就是拿这条立的。

### 数字：一句越界的话标价两次，钱那一边不动新代码

| 项 | 值 | 落点 |
| --- | --- | --- |
| 多带走的支数 | `CLAIM_UNITS = 2`（硬推本来是 1 支） | `resolveSale` 的 `units` 分支 |
| 当场 | `CLAIM_TRUST +4` / `CLAIM_COMPLIANCE −12` | 同一张收银记录上念出来 |
| 第二天早上 | `CLAIM_ASKBACK_TRUST −6`，只扣一次 | `applyDawn` + 合并进那张 `私域 · 微信` 卡 |
| 退货那天 | **退两支** | 走既有 `paybackCharge = order.amount`，**没写一分钱的新代码** |

退货翻倍不是新机制：`RISKY_RETURNS` 那条通道回账的是**整单金额**，而越界那一单金额就是 2 支的钱 —— 所以 ×2 是 `CLAIM_UNITS` 的自然结果。P19 那条"每笔动 sales 的钱各有一行 ¥"照旧成立（规则单测直接断言：整局只有小票 + 退货两行 `MONEY_LINE`，且 `ledgerSum === sales`）。

**为什么只做退一、不做赔三**：现实里这一句走的是《消保法》第五十五条（欺诈 → 退一赔三）。游戏只落"退回来两支"，因为三倍赔偿要引入一笔**不来自任何订单**的负现金流，而 P19 之后每一分钱都得能对回某一行台账 —— 那是新经济，不是新文案。这条边界写在这里，不留成隐含决定。

### 玩家看得见的那两句（措辞按核验过的条文收紧）

## P35：回音要对自己那笔账 —— 到期小样的日次门，和退货那句里的品类

P34 收尾时量到两个"后果对自己不诚实"的口子，这一轮一起补。两件事是同一类：**界面上那一句回音，说的必须是账上真的那一笔** —— 一个是时点（当天下午就扣了本该第二天才扣的分），一个是对象（退的是修护，念的是持妆）。

### 时点：`sample-expired` 也上日次门

- 病根和 P34 完全同源：`openFloorState` 里就调 `applyDawn`，而沙盘那颗「回到现场」（`src/CounterGame.tsx:181`）走的就是它。旗子 `sample-expired:<id>` 不带日次，于是当天回到现场 = 她已经回家看到批号了。
- 修法是把日次写进旗子本身（`sample-expired:<id>:<day>`），回音那一道加 `if (next.day <= day) continue;`，一过旗跟着变成 `expired-raised:<id>:<day>`。**没升 `SAVE_VERSION`**：`parseCampaign` 对 flags 只要求是字符串，新旧格式互读得动。
- **旧存档那面旗不带日次，按"今天之前派出去"处理（日次读成 0）**，所以隔天照样问回来一次 —— 改了格式不能顺手吞掉一次后果。这一条写在规则里也钉在测试里（`expired-raised:mei:0`）。
- 代价：改掉 P20 那一条的既有时点。原来的"当天问回来"没人依赖（沙盘/手机版都只断言"隔天问一次"），但第 3 天下午那一扣本来会让第 4 早少一次问句，两者不同屏所以没人发现。
- **判据踩到的坑（第一次跑就红了）**：想用 `sameDay.history.length === handed.history.length` 断言"没问就不多一行"，量到 `3 !== 2` —— 多的那一行是晨会每天自己写的读数（`晨会 · 昨天那条线达成 0%…`），不是回音。改成数 `history.filter(row => row.text.includes("批号"))`。同一个屏幕上一天加一行是常态，"没有新增行"从来不是这条因果的判据。

### 品类：那一句从票上读，不从台词里读

- 为什么会串：`risky` 只在一单的 fit 为 negative 时记进 `orders`（`campaign.ts:1454`），而一个人**有两种方向不对的货**（沈薇：持妆 / 修护）。P34 之前一人一单一品，所以台词里把品类写死看不出错；越界那一单退的就是修护，于是台账写"退了那单持妆"、晨会写"近看全是粉"，而账上退的是 ¥1,680 的精华。
- 定的不变量：**台词里可以出现品类名，但那一个名字只能来自小票**。落法三条：
  1. `RISKY_RETURNS[*]` 多两个可选字段 —— `{货}` 占位符 + `fallback`（旧存档没票时用哪一支）、`variants`（按票上那一支整句换掉）。
  2. 生成式只有一份：`paybackCopy(item, paybackProductOf(s, id))`，台账行和晨会卡都从它取。这正是 `memberRepeatLine` 那条先例（两处各写一遍就会在第二天早上错开）。
  3. `paybackCharge` 早就按 `order.amount` 退钱，所以这一轮**没有动任何钱的算式**，P19 的"每笔钱各有一行"不变。
- 只有两条需要 `variants`（沈薇、周姐），因为**只有那两句的抱怨本身跟货绑定**："镜头里全是粉感"是粉类产品的话，"持妆暗沉的对比图"是持妆的话。其余六条本来就不点品类（"你卖的东西""那单""套组"），不在这次范围内。
- **中途撤回的做法（记在这里以免下次再犯）**：一开始也给赵女士、安姐补了 `variants.soft`（"那套礼物"→"那支柔焦"），量的时候发现那两句压根不含品类名 —— 不是这个 bug 类，是量词洁癖，删掉了。判据（下面那条交叉检查）对它们同样有效，且不会因此变绿变红。
- 周姐那一句的品类原来写在**正文**里而不在 text 里，所以只有晨会那张卡会念错、台账行反倒是对的 —— 同一个错误在两处不对称，也是这次把 `{货}` 拉平的原因。
- 旧存档没票：金额和品类都只能估（`estimatedRiskAmount` 取推错方向里最贵那一支），所以那一句保持原样、一字不改。这条**故意钉成断言**（`沈薇退了那单持妆… · −¥1,680`），因为它是"估出来的那句和估出来的那笔"这对组合，不是漏改。

## P36：390×844 那两处 —— 一处是真的，一处是我自己量错的

### 一处真 defect：那颗按钮把"承诺"劈成了两半

`rescue-e2e/overclaim.spec.ts` 原有的六档几何探针只回答"折没折出格子"，不回答"折在哪里"。这一轮给它加了一条读数：逐字取 `Range` 矩形、按行的上沿分堆，记下**每一行从原文第几个字起**（`labelStarts`）。量到的：

| 档位 | `labelStarts` | 排出来 |
| --- | --- | --- |
| 1280×720 / 1280×800 / 1024×700 / 640×800 / 844×390 | `[0]` | 一行装得下 |
| **390×844** | `[0, 8]` | 「把话说满 · 承」/「**诺**两周淡斑」 |

`CLAIM_LABEL` 是「把话说满 · 承诺两周淡斑」，合法的断点只有第 5、第 7 个字前（那两个真空格）；第 8 个字起就是把动词劈开。这是 P34 那条「许它折行」的许可（`src/rescue.css` ≤650px 档 `.closing-buttons .floor-action button { white-space: normal }`）带出来的：当时量到 nowrap 让整行比行框宽 56px、第三格被推到屏幕外，于是放开折行 —— 而中文默认逐字可断，放开折行就等于放开断词。

**改法就落在那一条上**：`{ white-space: normal; word-break: keep-all; }`。许它折行，但断点收回标签自己那个空格（排成「把话说满 ·」/「承诺两周淡斑」），代价是零：按钮命中高仍是 58px、`overflowX`/`rowOverflow` 仍是 0、理由仍 4 行。**没有改文案**：「两周」是这句话里唯一可核查的时间承诺，为了排版把它删掉是把内容换成排版。

管辖边界写清楚：这条只管**按钮上的动作名**，不管它下面那行理由 —— 理由是散文，中文散文逐字折是正常排版，`keep-all` 加上去会让整段无处可断、直接撑破格子（`CLAIM_NOTE` 除了那副「 · 」没有任何空格）。

手机版那两颗（iphone / pixel-10）量的结果是 `labelStarts: [0]` —— 一行装得下，没有这个病。判据仍然钉进 `tests/overclaim.spec.ts`：这两档一旦将来把这句改长到要折行，断点也得落在空格上。

- **根 `AGENTS.md` 的日次数字与测试不一致**：那里写"清洁路线第 4 天 ¥16,750，第 5 天 ¥22,630"，而实测清洁路线逐日累计是 **4,620 / 6,090 / 8,050 / 14,770 / 22,930**（探针 `/tmp/p19-days.ts`；`runRoute` 的 `dayTotals` 是累计不是当日）。两个旧数字既不对应累计也不对应当日。本轮没动规则数值，所以没去改那句；按新规矩它属于"数值推导"，该由本文负责 —— 需要先确认那两个字段的原意再统一，不擅自改。
- **`.pawn-name small` 与 `.dock-person p` 在同一屏把同一个状态念两遍**：两处都调 `customerStatus()`（`src/CounterGame.tsx:277`、`370`），选中谁就在地图名牌下和面板里各看到一次「正在等你」。量到了，但它是**状态标签**不是那句话本身，且两处角色不同（地图认人 vs 面板读人），按本轮"只去重同一句话"的边界**保留**。若以后判定标签也算重复，这条要翻案。
