# 销售决策实验报告（SWE-2，T06）

- 目的：为「卖货过程重复、选择不够有意思」在三个候选决策里找出最成立的一个：
  **A 现在开单还是再探一次 / B 稳妥一件还是争取多件 / C 合适便宜款还是更贵款**。
- 代码来源：`/tmp/renqing-handoff-choice-20261018/baseline/dynamic-counter-prototype`（HEAD c88dd4d），只读导入真实引擎函数，未改一行源码。
- 实验目录：`/tmp/renqing-sales-swe2-20261018/`（audit.ts / scenarios.ts / proposal.ts / report.md）。
- 外部证据：负责人补充 `catalogue-audit.json`（32 客、看法 10、全知口径）；Grok 的 UI 发现已在 baseline 源码中核实。

## 结论先行

**推荐下一轮切片：C —— 把「正中」从「点头」里分出来，让已经存在的钱↔人情取舍变成玩家看得见的选择。**

理由一句话：C 的取舍在结算里真实存在（负责人证据 8/32 原味客；我的实验 29/160 含来访形态），玩家看不见它的唯一原因是 **`Consult.tried` 把正中（fit≥0.95，看法 +12）和对症（≥0.78，+8）都记成 `"positive"`，货架格子上都显示「点头」**。试的时候她说的那句话（「就是这个感觉」vs「这个可以」）一滑过去就没了，开单那一刻 +4 的差在界面上不存在。把这个标记保真 = 不碰任何结算规则、零经济风险、直接让 1/5–1/4 的接待出现真选择。

其余两项的裁决（详情见第三节）：

- **A（开单 vs 再探）现行规则全退化**：探只花不跨单的耐心，恒应探满。我另做了一个「问/试 −1 mood」的候选改法（proposal.ts），能把决策做真（515/402 分裂、266 场边际权衡），但它要动看法经济、有 world-sim 签名风险，属于「造选择」而非「显形已有选择」——按负责人「优先显形」的取舍，**A 留作备选，不推荐本轮做**。
- **B（稳妥 vs 多件）被反例推翻**：件数问出后「开口要满」158/160 场景严格不亏；残余形态只是「耐心见底没问出」的赌局。Grok 的「满分才许多件」我不附议——与本实验一致：21/32 本来只买一件，周姐/叶女士无可负担满分货，砍多件是删选择不是造选择。

## 一、现行规则的事实（怎么读出来的）

卖货链路：`openConsult → lookAt/askHer/tryOn（各花 1 点耐心）→ settleServe(货, 件数, mood)`。

- 耐心 4 点（急性子 −1，看法 ≥10 +1），本次接待的临时额度，不跨单；探的代价只有它。
- `Consult.mood` 累加、开单一起结；唯一来源是推销味那问（−3）。
- 适配分 `shelfFitScore`：demand 的 want/weight 加权，veto 未达标 ×0.35。档：≥0.78 positive / ≥0.55 mixed / 以下 negative；≥0.95 为正中（`PERFECT_MATCH`，看法 +12 而非 +8）。
- 结算：positive 卖开口数（预算与 maxUnits 截），mixed 只 1 件，negative 0 件 −3；超开口每件 −3；对症买不起 −1。
- `tryOn` 的台词已分两档（`score >= PERFECT_MATCH` →「就是这个感觉」，否则「这个可以」），**但 `tried[id]` 只存 FitTier 三档 → `TRIED_MARK` 一律显示「点头」**（consult.ts:269, 302；ConsultPanel.tsx:135-138；consult.css:51-53）。

**玩家点击「开单」前已知**：她说出口的诉求（看法 <10 只说权重最高一条）、客情笔记、预算（界面报数）、问出的件数上限、各货试用标记、tag 词与价。**不知道**：没说出的诉求、want/weight 数值、未揭开的底线、适配分、最佳货、maxUnits（没问的话）、以及——关键缺口——**哪一支试出来是正中**。

## 二、真实场景复现（全部真实 `beginSlot` 到场 + 真实 `settleServe` 结账）

命令：`cd /tmp/renqing-sales-swe2-20261018 && node --experimental-strip-types scenarios.ts`

### 场景 1：沈薇·初次（sim-0 第 1 天上午，真实开局客人）
已知：「一厚就假」（轻薄自然）、预算 ¥3,200、件数没问。
- 不探·按 tag 开粉霜×1 → ¥1,180 +12（三支含薄 tag 的全对症，验不验都成）
- 不探·开不含薄的持妆 → ¥0 −3
- 问件数+试粉底·开 3 件 → ¥2,940 +12。**探的全部收益来自「问出上限 3」那一下。**

### 场景 2：梁夏·初次（sim-0 第 6 天时段 2，自然到访）—— C 岔口实景
已知：轻薄自然、预算 ¥2,200。
- 试两支后开粉底×2 → **¥1,960 +8**；开粉霜 → **¥1,180 +12（正中）**。
- 两个都「对」：多 ¥780 vs 多 +4 看法。**但现行 UI 里两支都显示「点头」，玩家在开单界面分不清谁正中** —— 这就是要切的那一刀。

### 场景 3：陈导·初次（急性子耐心 3）—— B 残余形态
- 看+试面膜+问件数·开 2 件 → ¥1,160 +12；看+试乳液·不问件数硬要 2 件 → ¥1,760 +12（赌对，他上限真是 2）。
- **3 点耐心里「问件数」与「再试一支」互斥**——B 的真相是耐心分配题，只在耐心见底时存在。

### 场景 4：赵女士·替女儿买（buysFor）
- 看两处（第一处就看到「一直翻手机」= 脸不作数）+ 按 tag 开喷雾 → ¥680 +4；盲开面膜 → ¥580 +12（赌对）。
- 对她的「探」必须换成问/试——探的内容要变，探本身仍免费。

### 场景 5：何清·再见（真实接待一次 → 跨天再访，`chooseCode` 真实生效）
第 4 天她带「赶场」情境回来：**玩家已知变成「预算 ¥2,400（上浮 50%）、有件最要紧的事还没摸清」**。
- 盲开持妆 ¥1,280 +4（mixed，老口径的货今天不对）/ 盲开气垫 ¥760 +12（正中）。
- 老客笔记不再够用，**「再探一次」的信息价值在这里最大**——也是 C 岔口（持妆 ¥1,280/+4 vs 气垫 ¥760/+12）。

## 四、推荐切片：试用标记分出「正中」

**改动内容（全部在表现层，结算零改动）：**

1. `src/world/consult.ts`
   - `tryOn`：`tier === "positive" && score >= PERFECT_MATCH` 时记 `tried[id] = "perfect"`（`matched` 条件不变，两者口径本来就一致）。
   - `tried` 类型放宽为 `FitTier | "perfect"`；`TRIED_MARK` 加一档（建议 `perfect: "认准了"`，措辞按柜台惯例定，不许虚标）。
   - `restoreConsults` 的 tried 校验白名单加 `"perfect"`（旧档只含旧值，向后兼容）。
2. `src/world/ui/ConsultPanel.tsx` + `consult.css`：`tried-perfect` 的格子样式（与点头区分开即可）；`offerEvidence` 的「试用反应」一行自动跟着 `TRIED_MARK` 改，无需单独改。
3. `tests/consult-sim.ts`（测试文件，实施时同步）：`=== "positive"` 的取货/停止判定要把 perfect 排在 positive 前，否则盲策退步。

**成本**：零结算改动 → 签名、模拟、经济全部不动。唯一成本是枚举加一 + 两处展示。

**验收**：
- 梁夏真实场景：试粉底（点头）再试粉霜（正中）→ 两格一眼分清；开粉底×2 = ¥1,960/+8、开粉霜 = ¥1,180/+12，玩家在点击前能看见「多 ¥780 vs 多 +4 看法」。
- 8 位岔口客（catalogue-audit 名单）同样可验；无岔口的客人（安姐·面霜支配、沈薇·粉底支配）不制造假选择。
- `npm run test:rules` 不动结算即可全绿；需要补的只有 tried 枚举的测试断言。

**主要风险**：
- 岔口覆盖率天花板是现成的：约 1/5–1/4 接待有真两轴冲突，多数客人仍单点最优——本切片是「显形」，不是「普造」；若验收标准想要更大覆盖率，得另开内容侧切片（货架/诉求表），不是本项。
- +4 看法轴是长期收益（多说一条 / 多一句耐心 / 牵线 / 防抢的阈值），不是当场——`saleFeedback` 已教「为下一次见面铺路」，但玩家早期可能仍只认钱；这恰是该保留的真判断。
- consult-sim 盲策不改会退步（把 perfect 当普通 positive 报出顺序不变但优先级未体现）——一行级改动，已列进工作量。

## 五、备选与反例（留档，不推荐本轮做）

- **A·探取费（问/试 −1 mood，看免费）**：proposal.ts 全量证据。917 场景下盲开更优 515 / 探完更优 402；边际深度上 266 场（29%）出现同一客人内部「停早省心 vs 停晚多赚」的前沿。它确实把「再探一次」做成了真决策，但要动看法经济、有 world-sim 签名风险；若 C 显形后仍嫌接待单薄，这是下一个候选。
- **A·反例**：「第一下免费、之后才收」被自己的数据推翻——决定性信息总能落进免费那一下，边际前沿归零（0/917），与现状无别。**第一下不能免费**。
- **B·反例**：「满分才许多件」（Grok 提案）与本实验一致地不成立——21/32 客人本来只买一件，周姐/叶女士无可负担满分货；砍多件是删选择。
- **B·残余**：陈导图显示件数决策只在「耐心装不下问句」时以赌局存在，覆盖率太低，撑不起一个切片。

## 六、局限

- 「玩家会怎么选」用 consult-sim 同款盲策近似（固定顺序、tag 挑货）；比例会随策略漂移，但「两方向各有场合」「firstfree 退化」「B 全退化」这些方向性结论稳健。
- 场景取自前 10 天、6 种子自然/预约到场；未跑整季、未含周末单与 rival 动态；跨季老客只做了机制验证。
- 「看法」未折成钱——两轴胜负取决于玩家当周的路线（业绩/客情/守客），这正是要保留的真判断。
- world-sim 全量签名按约定未跑（本切片不动结算，按设计无签名影响；实施时仍以 test:rules + consult-sim 复核为准）。
