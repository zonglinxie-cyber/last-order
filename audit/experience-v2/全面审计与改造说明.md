# 《最后一单》全面审计与本轮改造

## 结论

**保留专柜题材和五日因果系统，推翻“用表单串起剧情”的呈现方式。**

游戏最有价值的不是护肤知识问答，也不是堆 AI 对话，而是：**当业绩、人情和职业底线同时向你要东西，你怎么选？**

本轮已经完成可运行的第一轮改造，不是只写方案。但尚不能称为商业成品：可重复游玩的策略深度、统一角色美术、音画演出仍需要下一轮投入。

### 范围与证据

- 实际主项目：`src/main.tsx` → `CounterGame.tsx`，另有 `RushGame.tsx` 90 秒挑战。目录名“AI公司大乱斗”不等于当前游戏题材。
- 规则共用：`dynamic-counter-prototype/src/campaign.ts`。没有创建第二份销售经济，没有降低 ¥21,000 目标。
- 检查了主入口、规则、存档、挑战循环、素材、已有测试；进行了本机 Chromium 自动化交互及截图检查。
- 新 UI 作用于根目录网页；手机 PWA 只继承共用规则修复，不宣称它也换上了新 UI。
- 本轮没有访问认证文件、调用外部模型、安装依赖、提交 Git 或发布线上。
- 事实、设计判断、未验证项在下文分开陈述。趣味性评价属于设计判断，不是用户调研结果。

## 最重要的三个问题

1. **世界没有兑现自己的规则。** 拒绝也算“接待过”，原闭店事件拿它当成交；没有订单也会争归属或索要赠品。破坏的不只是数值，是玩家对故事的信任。
2. **玩家在执行流程，而不充分理解判断。** 手机藏掉商品用途，旧线索不便回看，提问后无法主动追问，正确问题总排在首位。
3. **好的内容被后台式界面埋住。** 开场同时展示顾客、业绩、日志和流程；剧情的角色反应虽然写在规则里，却没有被保存并展示。

## 六个维度审计

### 1. 故事性：有好冲突，缺少兑现与演出

**已观察**

- 五天主题各有区别：入口竞争、同事抢归属、替别人买礼物、大客越权、最终盘点。
- 核心人物动机清楚，赠品缺口、让单、人情回报和退货已经有跨日逻辑。这是应保留的资产。
- `EventChoice.result` 原本没有进入根入口的剧情反馈；玩家点选后直接进入账本，错过角色反应。
- 第四天文案把第二天周姐的接待称作“昨天”。第三天又把已完成订单写成“准备付款”。
- 原 `dayServed` 同时包含成交与拒绝，用它判断付费事件，会制造虚假剧情。

**本轮落地**

- 开场改成“你是谁、五天内要什么、谁在向你施压”，不再先给后台面板。
- 每日加入人物引言、核心冲突问题和五章进度线；不提前透露尚未发生的结果。
- 闭店事件呈现说话人的真实素材；决定后的回应写入因果账本，刷新仍保留。
- 付费事件检查真实订单或旧存档明确的成交标记，不以“接待结束”冒充购买。
- 安姐未成交时改为苏蔓的交接/复盘场景，不再凭空索要赠品。
- 修正上述时间和付款阶段的叙述矛盾。

**仍需下一轮**

- 角色弧线仍主要靠短文本；缺少表情、站位、停顿和对白交锋。
- 好人路线相对明显。真正的灰度应是两个合理价值的冲突，而不是把坏选项写得更坏。
- 无订单路线最终的储备人选对话仍较泛化，可按业绩与合规分别写版本。

### 2. 交互：让玩家知道自己花了什么、知道了什么

**已观察**

- 现场按真实时间走，接待按动作走。这套规则有价值，但首次使用者不容易理解。
- 原接待重点展示最后一条线索和最后一句话，信息会在流程推进时“消失”。
- 原重开弹窗缺少完整焦点管理；手机版右侧栏消失后，顾客选择更依赖拥挤地图。
- 地图可被拖离可见区；底部滚动位置可能沿用上一阶段。

**本轮落地**

- 显示阅读暂停、动作成本及另一位顾客剩余耐心。
- 新增接待手记，只记录玩家确实观察和问到的内容，不泄露 `bestProduct` 或未发现线索。
- 试用前可再问一句，真实消耗时间与体力，并保留问答；可以取消追问而不扣时间。
- 增加移动端现场选客按钮、地图放大和有界拖动，保留“选人检查 → 开始接待”。
- 步骤改变时复位操作区滚动位置；错误试用换款时，步骤正确回到试用阶段。
- 值班手册暂停现场；弹窗隔离背景焦点，支持 Tab 循环、Escape 和关闭后焦点归还。
- 自由输入明确标注为本地剧本回复，避免暗示已接通真实 AI。

**仍需下一轮**

- 观察热区坐标对所有人物复用，第三天的手机/成分截图线索仍借用了脸部热区。这是语义不一致，不应把它当成真正的皮肤识别。
- 桌面与手机仍有独立滚动区域；后续可把复杂接待拆为更自然的上下分层，但需真机验证手势。

### 3. UI：从管理后台转向“柜台里的故事”

**已观察**

- 旧开场的信息密度偏后台，核心行动和主人公都不突出。
- 主场景、接待操作、账本始终使用相近布局，空间没有随任务变化。
- 手机原商品用途被 CSS 隐藏，玩家只看到名称和价格，不能充分判断。

**本轮落地**

- 墨紫、暖纸金和旧玫瑰色统一视觉层级；开场使用大字标题、人物海报和五章刻度。
- 开场/章节页移除无关侧栏和接待底栏，突出一个主按钮。
- 现场增加当前冲突提示，保留商场沙盘而不是改成数据卡列表。
- 商品用途在手机上也显示，价格不再是唯一信息。
- 结算和结局压缩无用底部留白，把更多空间还给因果账本；结局展示业绩、信任、合规三个维度。
- 全局手册提供玩法、商品、人际关系和历史记录入口。

**验收范围**

- 自动化检查 1440×900、390×844、320×568、844×390 的开场可达性和页面横向溢出。
- 390×844 验证接待、试用、成交可操作；成交按钮留在视口中，核心按钮保持至少 44px。
- 小屏开场允许滚动，不宣称所有信息必须首屏完整容纳。
- 没做全套 WCAG 对比度审计和真实读屏测试。

### 4. 玩法：修复公平性，但不伪装成已经有很深的策略

**已观察**

- 资源具有实际作用：注意力、耐心、体力、小样、关系、订单归属。
- 观察→提问→试用具有学习顺序；错误可以拒绝或换品，后果跨日保留。
- 当前 9 个顾客身份的最佳产品仅分布在柔焦和修护，**持妆没有正向最佳案例**。
- 适配本质是单一 `bestProduct` 判断。反复游玩后容易记答案，随机调整选项位置不能解决这一点。
- 文案曾称持妆“高提成”，但规则没有独立提成系统。这是没有机制支撑的承诺，已去掉。
- 原唐可分单固定扣 ¥490、让单固定扣 ¥980，即使实际错误订单不是 ¥980；订单记录未同步改变，后续退货还会多扣。
- 超额赠品选择原来不检查足够库存，而是扣到零即止。

**本轮落地**

- 让单按实际入账金额转移，订单本人份额同步减少；后续只退本人剩余份额。
- 兼容缺少 `orders` 字段但保留成交/转单标记的旧 version 2 存档。
- 库存少于四份时，不提供需要四份额外库存的赠品选项；底层规则也拒绝绕过。
- 提问位置按人物确定性轮换，仍按原规则索引判断；增加追问给玩家纠正判断的机会。
- 保留五日金额和结局条件，不用调低目标伪造“更好玩”。

**建议的下一轮核心重构（未实施）**

- 把“一个顾客一个标准答案”改为三个维度：使用者/使用场景、皮肤风险、预算与时间。
- 每个商品至少两种合理场景、两种不合适场景；持妆必须有真正的正向需求。
- 一位顾客允许“安全小单”“高投入完整方案”“主动不卖”三条可解释结果，而不是只用产品 ID 决定。
- 给高风险收益以明确代价，但不要用百分比随机背刺替代可观察线索。
- 新规则需独立平衡实验，并重新走完五天；不能直接塞入现有存档假装兼容。

### 5. 趣味性：主线负责牵挂，挑战负责手感

**设计判断**

- 五日故事的乐趣是“之前做的事回来找你”；90 秒挑战的乐趣是“跑得更快、连单不断”。两者不是同一种体验，不应强行共享业绩。
- 旧主线少了一次“我刚才的选择让她怎样了”的反馈，导致本来存在的因果缺少情感重量。
- 挑战已有冲刺、打断竞争、连击、高光和客流阶段，是可保留的即时循环。

**本轮落地**

- 章节悬念、人物回应、可回看的账本强化主线反馈。
- 两个模式入口明确标注，挑战独立计分、独立存档，不把街机表现塞进剧情收入。
- 回归验证挑战从取货、送达、得分到暂停刷新续玩的真实界面流程。

**未验证与下一轮**

- 没有真实玩家留存/二周目率数据，不能声称“更上瘾”或趣味性提升某个百分比。
- 建议找 5 位没读文档的玩家：观察是否在 60 秒内理解目标、是否说得出上一笔选择的后果、是否主动想重开。
- 主线可增加三类局末复盘：你放走了谁、谁会回来、哪笔账仍没结；需依据真实状态生成，避免编造后果。
- 街机的新关卡/动态任务不在本轮实现范围；本轮没有重平衡 90 秒挑战难度。

### 6. 美工与性能：先做好可读性和素材交付，再谈重画

**已观察**

- 项目已有商场场景、实名人物、客户近景和真实商品画，不能退回匿名圆点或 CSS 瓶子。
- 员工偏 Q 版、顾客近景偏写实；不同层级可有风格区别，但当前缺少统一的光线、表情与镜头规范。
- 七张顾客近景加商品图原始总量为 **16,562,582 字节**；小头像原来直接用大图。

**本轮落地**

- 保留所有原图，重新组织开场人物海报、事件肖像、商品说明和色彩，不冒称整套美术已重画。
- 新增 WebP 衍生图，完整近景保留 853×1844 坐标几何，不破坏观察热区。
- 上述八张完整 WebP 合计 **1,360,240 字节**，较原图减少 **91.8%**；七张 148px 宽缩略图合计 **70,244 字节**。
- 头像列表、底栏和挑战小票改用缩略图；近景用完整 WebP。原始 PNG 保留为编辑源。
- 压缩是有损的，质量参数 88；已看图核对主要画面，不宣称像素无损或页面提速 91.8%。
- 可重复构建脚本：`node scripts/optimize-art.mjs`，使用本机已有 `cwebp`。日常运行无需该工具。

**后续美术规范**

1. 场景继续用 2.5D 专柜，不换引擎。
2. 员工/客户各建立平静、质疑、认可、失望四个可复用表情；锁定脸部线索坐标。
3. 商品使用统一机位、大小与透明底，建立与三个用途对应的形状标识，不只靠颜色。
4. 补专柜环境声、收据声和轻量角色反馈；给独立音量与静音开关。
5. 重绘手机版素材必须遵循该目录既有导出约定，不顺手改移动运行时。
6. 原素材来源、肖像授权和商用版权本轮未核验；发布前另行审查。

## 验证与恢复

- 改动前：根目录 `npm test` 通过；基线日志 `baseline-test.log`。
- 缺陷探针先复现四组失败：`bug-reproduction.log`，再修改规则并补充旧存档兼容测试。
- 最终命令及结果见 `验收记录.md`，不以构建成功替代游戏验证。
- `before/source.tar.gz` 保存本轮修改前主源码、测试、规则、README、package；`before/existing.patch` 与 `before/status.txt` 保存原有 Git 差异和未提交状态。
- 不要直接整仓回滚：工作区原本已有大量用户未提交修改。本轮没有 reset、stash、删除原素材或提交。

## 如果允许进一步推翻设定

优先推翻的是**玩法抽象，而非题材**：从“柜姐销售问答”改为“限时的职业判断与人情债务游戏”。

下一版可以把一笔接待拆成四个有意义的承诺：**花多少时间、承诺什么效果、谁拿业绩、谁承担售后**。每个承诺都必须出现在当日反馈和后续账本里。镜头、文案、试用都为这些决定服务，不再让玩家完成一串没有取舍的点击。

这部分是后续设计方向，不是本轮已实现功能。
