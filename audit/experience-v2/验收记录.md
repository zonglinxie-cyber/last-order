## 追加：台账念成一句话（2026-09-24 · 去面板感第一轮）

合规原来是两个 UI 里各一个裸分数加四条硬编码的 `>= 50`，结局判的线和界面显示的不是同一处。现在规则里只有一条 `COMPLIANCE_RISK` 和一个 `complianceWord()`：沙盘右侧栏、手机版今日账单、结局的 `safe` 三处同源，界面上不再出现「合规 47」这种数字。

命令与标记行（未拼接管道，退出码单独取）：

- 根目录 `npm test` → `ROOT_NPM_TEST=0`；`ℹ tests 35 / pass 35 / fail 0`（规则，含新增的合规同线用例）、`ℹ tests 18 / pass 18 / fail 0`（挑战）、`✓ built in 123ms`、`44 passed (57.8s)`（沙盘 e2e）。
- 手机版 `npm test` → `MOBILE_NPM_TEST=0`；`ℹ tests 35 / pass 35 / fail 0`（规则）、`✓ built in 120ms`、`36 passed (12.0s)`（运行时，比上一轮多一条今日账单用例）、`1 passed (1.3s)`（发布离线验收）、`ℹ pass 5 / ℹ fail 0`（sites）、`npm run check:runtime` → `CHECK_RUNTIME=0` + `Mobile runtime integrity check passed (28 protected files)`。
- 上一轮偶发的 `tests/mobile-runtime.spec.ts` 键盘用例这次在 8 worker 全量跑里通过，未放宽任何断言。

现场走查证据：`morning-standing.png` 是沙盘栏位，「台账还压得住」和上面那句柜位评价同一种排法，没有进度条也没有分数；`mobile-summary-ledger-line.png`（40 分）与 `mobile-summary-ledger-line-calm.png`（80 分）是手机版今日账单，同一句话换颜色。

第一次截图暴露两个真问题，不是猜出来的：这句话被 `.summary-screen>p` 的 `text-align:center` 和 8px 压住了，看着像日期行。修法是选择器升到 `.summary-screen .summary-compliance`，并把 `@media (min-width:0)` 里的条目一起升上去；现在用例直接断言 `text-align=left`、`font-size=12px`、风险色 `rgb(224, 166, 141)`、平静色 `rgb(204, 185, 173)`，排版规则改回去会立刻红。

本轮仍未验证：没做真实玩家试玩；`complianceWord` 四档文案只按分档边界核过，没做真人可读性测试；沙盘栏位在窄视口（<1280）下的换行未逐一截图；界面去面板感只动了台账，体力/证据的裸数字和 `.target-track` 进度条仍在。
