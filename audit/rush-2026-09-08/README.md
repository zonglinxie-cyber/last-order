# 闭店大作战 · 2026-09-08

这一轮按用户“参考网上小游戏、跳出原有规则”的方向，完成一个可以直接玩的 90 秒即时送货挑战。进入方式是主界面顶栏「闭店大作战」或 `?mode=rush`。主界面的五日故事和既有未提交改动保留，修改前恢复点在 `before/`。

## 参考与取舍

- [Little Ritual](https://developers.openai.com/showcase/little-ritual)：参考移动、取货、送达组成的直接操作循环。案例页标注 GPT-6 Astra。
- [Codex Pet Arena](https://developers.openai.com/showcase/codex-pet-arena)：参考会主动竞争的对手、短周期阶段变化、加速能力和即时反馈。
- [MiniTown](https://developers.openai.com/showcase/minitown)：参考可观察的现场变化；本轮没有另做城建系统。

调研读取了案例介绍和开发过程，没有亲自玩完外站演示，也不将“画面惊艳”或“好玩”当作已被测试证明的结论。

现有接待入口实看见 `01-before.png`：人物素材明确，下一步也清楚，但玩家主要按固定顺序点击观察、提问、试用。新模式把操作重点放到跑动路线、谁先送、何时冲刺以及连单是否值得冒险上。这里只检查了原版这一接待状态，其完整五日流程另由原有浏览器回归覆盖。

## 玩法与文件

`src/RushGame.tsx` 管理展示、键鼠/触控、相机、声音和本机保存。`src/rush-rules.ts` 管理移动、绕障、计时、顾客耐心、对手、冲刺、积分和存档校验。`src/rush.css` 为新模式样式。

- 点货台或底栏商品取货，点顾客或订单送达。键盘支持 WASD / 方向键、E、1/2/3、空格、P / Escape。
- 连对三单触发八秒加速与双倍得分；错货扣分、保留手中商品，并打断连单。
- 陆遥要走到顾客身边并交谈才会抢走顾客；附近发动冲刺能打断三秒。
- 三十秒后加快来客，最后二十秒进一步加快，九十秒后冻结结果。后续补货需求由种子随机生成。
- 手机尺寸采用跟随人物的视角，底栏商品和订单可直接操作。
- 暂停、刷新续玩、窗口失焦、切后台、结算、再来一局、暂停时确认重开均已实现。
- 仅在结算后更新个人最佳。挑战积分不进入五日销售账本。使用独立存档键，单独校验；每秒保存，状态切换和离页补存。

本轮没有修改 `dynamic-counter-prototype/` 源文件。核对该目录的 Git 差异与 `before/existing-changes.patch` 一致。没有更换引擎、部署线上或调用外部模型。

## 验证

最终 `npm test` 退出码 0，原始输出在 `final-test.log`：17 项既有规则测试、11 项挑战规则测试、生产构建、5 项主入口浏览器测试通过。主入口浏览器测试包含完整五日、刷新、拒绝、拼单和手机尺寸操作。

内置浏览器通过可见 UI 操作的新模式证据：

1. **开场与开始**：桌面开场见 `02-rush-intro.png`；手机开场见 `07-phone-intro.png`（相机调整前）。鼠标开始和空格激活开始按钮均验证。
2. **取货、送达与高光**：桌面取货后才入手，送达后加分。`03-rush-play.png` 展示五连单阶段。手机先完成八连单，再用跟随视角完成三单，达到 6,570 分、十一连单，见 `08-phone-camera.png`。可见操作记录保存在 `ui-play.json`。
3. **拒绝**：主动拿持妆送给要求柔焦的沈薇，出现“这不是我要的”，积分仍为 0，手中仍拿持妆。结果见 `ui-wrong-product.json`。
4. **暂停与续局**：首局在 134 分、剩余 72 秒暂停后刷新，状态一致；错货后持货刷新也保留商品并暂停。手机暂停见 `04-phone-pause.png`。
5. **打烊与重玩**：一局自然到达 00:00，结算 2,246 分、7 单、最高 6 连单，见 `06-phone-result.png`。该局包括操作停顿和顾客流失，并非完整无失误通关。结算后重玩归零。暂停重开的取消保留 6,570 分，确认后归零，已有结算纪录保留。
6. **返回五日故事**：返回后仍为原有第 1 天、19:00、沈薇接待、0 处线索、尚差 ¥21,000，随后从顶栏回到挑战。没有改写原接待。

过程中修复了三项实际问题：抽样路线漏过柜角导致人物进入家具并使存档失效；手机网格被旧宽度撑出屏幕；对手图层挡住顾客点击。最终手机送达已复验，路线与任意时刻存档有回归测试。

可达性验证限于可见文字、键盘开局、按钮操作和弹窗焦点管理；没有做完整屏幕阅读器审计。手机验证为 390×844 浏览器视口，不代表真实 iPhone / Android、触屏多指操作或 PWA 离线测试。音效创建无控制台错误，但本轮没有听觉评测。新模式的长期耐玩性与难度仍需真人反馈。
