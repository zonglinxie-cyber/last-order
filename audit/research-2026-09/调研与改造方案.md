## 二、外部调研结论（有来源）

1. **"内容多"的观感来自系统性，不是文本量。** RimWorld 的 RimTalk 让殖民者互相对话而非玩家读台词，作者称用户量接近三倍（[player2.blog](https://blog.player2.game/p/how-one-rimworld-modder-tripled-his)）；生成式代理沙盒里 25 个 agent 仅凭一个目标就自传出邀请、协调赴约（[Generative Agents, arXiv](https://arxiv.org/abs/2304.03442)、[Ars Technica](https://arstechnica.com/information-technology/2023/04/surprising-things-happen-when-you-put-25-ai-agents-together-in-an-rpg-town/)）。可迁移的不是 LLM，而是"每个在场角色有目标 + 计时器 + 会互相打断"。
2. **玩家动作应指向场景内实体，而不是点表单。** RCT 用思想泡泡和表情直接暴露小人意图（[Rollercoaster Tycoon 机制分析](https://jurgengravestein.substack.com/p/breaking-news-rollercoaster-tycoons)）；状态用位置/姿势/气泡表达，仪表盘只做二级查看。
3. **"按流程服务顾客"这个母题本身能火。** 沙威玛传奇 2024 年抖音 26 亿播放、App Store 270 万下载、界面被评测认为"简陋"仍成立，关键是限时逐单手工艺 + 顾客本身是干扰源（[界面新闻](https://www.jiemian.com/article/11935940.html)）；Good Pizza, Great Pizza 的订单以含糊描述给出，玩家从话里提取配方（[订单机制](https://good-pizza-great-pizza.fandom.com/wiki/List_of_orders)）；VA-11 Hall-A 靠"从对话反推需求、不给提示"（[Game Developer 拆解](https://www.gamedeveloper.com/design/a-breakdown-of-the-drink-choice-mechanic-in-sukeban-games-i-va-11-hall-a-i-)）。→ 本案的正确方向是**加深信息不对称**，不是把线索打勾变简单。
4. **同类最容易做坏的地方就是簿理化。** Supermarket Simulator 被批"看不出哪些进价涨了"、雇人后失去乐趣（[GameTyrant](https://gametyrant.com/news/supermarket-simulator-review-why-are-these-games-so-addicting)、[GameSpew](https://www.gamespew.com/2025/11/supermarket-simulator-review/)）；Two Point 被批" endless list of tasks"（[GamingBible](https://www.gamingbible.com/reviews/two-point-museum-review-649636-20250219)）；中国式网游把"数值面板堆砌"当讽刺对象反而卖 40 万份（[游戏大观](http://www.gamelook.com.cn/2024/07/549853/)）。→ 新增数值必须表现为对话内符号，不能再加侧栏面板。
5. **纯 DOM/React 的边界。** 通行做法是场景走渲染层、UI 走 DOM（AI Town = React + PixiJS，[repo](https://github.com/a16z-infra/ai-town)）；只有 transform/opacity 走合成器线程（[web.dev](https://web.dev/articles/animations-and-performance)）；行走动画用 `steps()` 切帧（[MDN steps()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps)）；遮挡按脚部 y 排 z-index；点击寻路用 A*/可见图（[Red Blob](https://www.redblobgames.com/pathfinding/a-star/introduction.html)）。数十个动画实体是 DOM 的舒适上限——本案现场 ≤ 12 人，可行。

## 三、行业素材（内容深度的真实抓手）

- 门店指标口径：客单价=金额÷笔数、连带率=件数÷小票数、坪效、售罄率、进店率/体验率/成交率/回头率（[C2CC 六指标](https://www.c2cc.cn/news/68833.html)、[术语](https://www.sohu.com/a/541234351_121124546)）。
- 晨会/午会/晚会做一对一场景销售模拟；"严禁仓库有库存、货架无陈列"；新老店员差距最大的是连带率（[品观网培训文](https://www.pinguan.com/article/content/6646)）。
- KPI 普遍完不成、大促才达标、自掏腰包囤货、完不成要交改进报告（[虎嗅](https://www.huxiu.com/article/3853749.html)）；礼盒预算从 8000–10000 降到 5000–6000 才算大单（同源）。
- 换货时销售额会算到另一个柜姐头上，公司明令禁止抢单但新人被要求把单"吐"出来；老员工不指导新人因为业绩互斥（[界面 · 柜姐自述](https://www.jiemian.com/article/4835944.html)）→ 直接支撑"订单归属"机制。
- 小样/中样是非卖品，只赠不售，贴标违规会被罚（[新华网](http://www.news.cn/fashion/20230616/8f23f9beeb4c47d8af81560e14ed7386/c.html)）→ 支撑赠品合规线。
- 高端美妆占百货销售约 85.7%、"顶柜"月销破亿、美容坊带动 30% 销售（[CBNData](https://www.cbndata.com/information/282258)）；一楼位置会被坪效更高的品类换掉、SK-II 关柜同时高端美妆柜台数增长（[新华网](http://www.news.cn/fashion/20250311/5da68a9ed3bc4f94a0cffeecc1a50726/c.html)）→ 支撑"柜台位置/撤柜"压力。
- 私域：月复购 10–15%、加一个企微好友成本 20–30 元、DM 加粉率 10–20%（[CBNData](https://www.cbndata.com/information/112436)）；春节"每天一车车发货"、老客闪送到家、社群清货（[界面](https://www.jiemian.com/article/14016764.html)）→ 支撑"加微信 / call 客"机制。
- 国货高端靠妆教成交：岗位称"化妆师"、先问肤质和需求、工作日可约满、体验者"鲜少空手离开"（[钛媒体 · 毛戈平](https://www.tmtpost.com/7954413.html)）；IPSA 用肌肤测试仪测纹理/锁水/皮脂/透明感/弹力再出方案（[IPSA 官网](https://www.ipsa.com.cn/testSkin.html)）→ 支撑"试用/仪器"作为信息获取动作。
- 巡店必查手工账与电脑账核对、达标率与时间进度差距、畅滞销与进销存（[搜狐](https://www.sohu.com/a/901886206_121123733)）；神秘顾客按事前项目拍照取证、数值化呈现（[AJIS](https://www.ajis-group.com.cn/index.php?m=content&a=index&classid=2&id=4)）→ 支撑第 5 天巡店事件读玩家留痕。
- 退货归属"没有统一答案，由企业业绩归属与激励制度决定"（[盖雅](https://www.gaiaworks.cn/post/gaiaworks-news-202608277)）→ 现有"冲回本人份额"是设定，不是行业定例，可以在游戏内成为被争夺的规则。

### 三-B、价格与赠品合规（P32「电商比价那一格」的出处，补充于 2026-09-25）

- 《明码标价和禁止价格欺诈规定》（市场监管总局令，2022 年 7 月 1 日施行）里与"她拿截图来要求退差价"直接相关的四条，按地方市场监管部门的重点内容解读转述：
  - 第十六条：标明的**被比较价格信息应当真实准确**；折价、减价、价格比较要有实际成交依据（前七日内没有交易的，不应高于本次比较前最后一次交易价格）；与厂商建议零售价比较的应当明确标示来源。
  - 第十七条：**不得在折价、减价前临时显著提高标示价格** —— 也就是"先涨后降"这条线。
  - 第十八条：采取赠品形式促销的，**赠品的品名、数量应当标示**。
  - 第十九条：不得**不标示或者显著弱化标示对消费者不利的价格条件**，不得以虚假折价、减价或价格比较方式销售。
  - 来源：[《明码标价和禁止价格欺诈规定》重点内容解读（地方政务网）](https://www.bp.gov.cn/html/BPSZF/202305/0168490280057122.html)、[《重点内容解读》（重庆市潼南区市场监管局）](https://scjgj.cq.gov.cn/zz/tlq/zwgk/zcjd_146798/202211/t20221102_11256869.html)。总局原文页 [ moj.gov.cn ](https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/202305/t20230511_478601.html) 在本机抓取时重定向失败，故上面按解读文转述，条款号与措辞以正式文本为准。
- "价保 / 退差价"在 2026 年已经是消费者熟悉到会主动主张的动作：618 期间价格保护成为投诉重灾区，有案例实付 845 元并获赠多件小样、价保周期内裸价降到 765 元最终只返 12 元，也有商家用新链接降价绕开价保入口（[21 财经](https://www.21jingji.com/article/20260605/herald/93cfc777acf162048e8b7def0ad6244d.html)）。
  - 证据等级要写清：该文记录的是**线上平台内**的价保纠纷，不是"顾客到专柜拿旗舰店截图比价"的现成案例。后者在这里是推论 —— 专柜价与官方旗舰店券后价长期存在价差（[经济观察报：国内外"区别对待"的化妆品专柜](http://www.eeo.com.cn/2017/0426/303282.shtml)），叠加价保被普及成默认预期，才使这一击在真实柜台成立。
- 落到游戏里（`campaign.ts` 的 `priceCards` / `priceEcho`）：
  - 柜台 BA **没有改票面的权限**，所以这一格两条答案都不动 `sales`、不产生 ¥ 台账行 —— 这是价格机制，不是数字奖励。
  - "讲价盘"对应第十六条（说清被比较价的来源与依据）：合规 +5；有没有她微信决定这句话传不传得出去（私域渠道，见第三节）。
  - "垫两支小样"对应第十八条的反面：未标示、未登记的私下补差 → 合规 −8、抽屉少两支、第 4 晚苏蔓问出那两支的去向。
  - 不设"退差价"这一格：那是店员无权做的动作，写进去等于教玩家一件假事。

## 四、改造方案（四层，按依赖顺序）

**P1 可玩性内核：把"答案钥匙"换成"带信息不对称的多目标匹配"**
- 产品加属性轴（自然妆感 / 即时改善 / 舒缓 / 刺激风险 / 价格），顾客加需求权重 + 硬禁忌 + 预算 + 可承受连带件数。
- 适配度是连续分数，产生三档结果（满意 / 勉强且留售后风险 / 拒绝），金额由"满足度 × 连带 × 预算"推导，不再写死 `sale`/`wrongSale`。
- 需求默认部分隐藏：只有观察到对应线索、或问到关键点，才在 UI 中显示；未观察到的需求仍参与计算 → 玩家可能"选对了看得见的部分"而翻车。
- 试用改为提供新信息（揭示该产品的真实反应），换款消耗体力与时间 → 四步节奏不变（符合根 `AGENTS.md:4`），但每步都影响结局。
- 让 `evidence`、关系、合规真正进入结算与结局判定；删除或接通 17 个死 flag。

**P2 互动性与前端：让现场自己运转**
- 把 `rush-rules.ts` 的几何层（`walkable/clearLine/route`）提为共用模块，主沙盘获得真实寻路与绕行。
- 复用手机版行走帧（`*-walk.png` + `steps()`），按脚部 y 排遮挡。
- NPC 目标驱动：陆遥会走向耐心最低的客人并当面递试色、苏蔓 call 老客、罗曼巡场查陈列、唐可开播拉客；玩家通过"点人→指派/打断"干预，事件用思想泡泡预告（RCT 式）。
- 保持"玩家不是地图上的自主小人"这条手机版约定（`dynamic-counter-prototype/AGENTS.md:11-13,27`）：自主化的是 NPC，玩家权力仍是注意力、指派与资源。

**P3 内容深度：把行业机制变成可玩系统**
- 晨会开场：今日指标（达成率 vs 时间进度、新品占比）以柜长话术给出，不做面板。
- 连带与客单价：由 P1 的件数选择产生，直接影响 ¥21,000 能否达成。
- 会员/私域：成交后可选择"加微信"（消耗时间与话术质量），次日 call 客召回，复用现有 dawn notice 通道。
- 小样合规：非卖品只赠不售，超额未登记 → 盘点缺口 → 第 5 天巡店按留痕取证（读 `evidence`/flag）。
- 柜台位置压力：连续未达标触发"卡位/撤柜"叙事后果。

**P4 UI：去面板化**
- 接待界面保留面部近景为主玩面，把 `1·观察 2·提问 3·试用 4·成交` 步骤条降为弱进度；等待与压力用现场符号表达。
- 右侧 rail 三段文本与新面板合并，避免同类被批的"仪表盘化"。

## 五、验收口径

- 每层完成后：根目录 `npm test`（规则 + 构建 + 12 项 e2e）与手机版 `npm run check:runtime`、`npm run build`、`npm run test:runtime` 全绿。
- 数值改动必须从 UI 完整走一遍重新测量，不允许只改断言数字（根 `AGENTS.md:10`）。新的第 4/5 天数字与达成路线记入本目录验收记录。
- 前端改动必须在浏览器实测（点击、走动、倍速、存档刷新），并说明未验证项。
